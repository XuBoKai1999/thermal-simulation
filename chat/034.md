# ADR01 bootstrap validation and provenance corrections

Reviewed the clean `main` working tree at commit `015d9dc7` and made three
localized corrections without changing the accepted architecture.

`run/01_ADR01/workflow.py` now captures the starting commit SHA and dirty state
immediately after validating the plan and before importing the runner or creating
the scenario directory. The final manifest uses those captured values, so newly
generated scenario output cannot alter its own provenance.

S0 now runs only its selected production timestep. It is recorded with
`validation_basis: accepted_baseline`, `local_validation_pass: null`, and
`trajectory_validation_state: VALIDATED_BASELINE`; it advances
`validated_through_s` to its endpoint. Automatic same-checkpoint `dt` versus
`dt/2` reference execution begins at S1. Later warn/strict and accumulated
validity behavior is unchanged. The existing self-test now covers the bootstrap,
pass, failure, and downstream-unvalidated state sequence.

The stale threshold-crossing approval claim was removed from
`segmented-workflow.md`, and `handoff.md` now describes S0 as the bootstrap and
the accepted status as S0/S1/S2 accepted with only S3/S4 unvalidated.

Regression results: Python compilation and workflow self-test passed. A real
1.25 ms strict-mode workflow run confirmed no S0 reference branch, an S1 `dt/2`
reference branch, strict stop on S1 failure, `validated_through_s=0.00025`, and
four unique production summary times (`0`, `0.00025`, `0.00075`, `0.00125`).
Physical-time dump/checkpoint names remained unchanged. Its manifest recorded
commit `015d9dc70ba2ecc4d6989a1572532b5f94a8619d` and the dirty state that existed
before output creation. Temporary plan and generated regression output were
removed. The full 0-420 s simulation was not run.
