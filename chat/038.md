# ADR01 long-time restart orchestration

Added the approved case-level `run/01_ADR01/restart.py` entry point without
changing the workflow architecture, solver, physics, timestep integrator, or
checkpoint format. It is fixed by default to parent `baseline-v1` at 420 s and
child `baseline-v1-cont-420s-1800s`, ending at 1800 s with dt/summary cadence 2 s,
heavy output cadence 10 s, and progress cadence 10 steps.

Before creating the child, it requires the parent manifest and checkpoint,
checkpoint format v1, exact 420 s time, current mesh identity, a finite vector
whose size matches the parent DOF count, parent end time at least 420 s, and
parent validation through 420 s. Failures emit an ERROR and re-raise. The only
small `main.run()` extension is an initial-observation callback after existing
checkpoint restore/summarization but before any transient timestep. `restart.py`
uses it to compare six parent/child scalar diagnostics at 420 s with
`rtol=atol=1e-12`; it does not duplicate state restore or run a check timestep.

The child has its own log, summary, manifest, checkpoints, dumps, and PVD. Its
manifest records parent lineage and `restart_continuity_status=PASS`, but
`validation_status=NOT_PERFORMED` and `validated_through_s=420`; reaching 1800 s
will not extend validation evidence. No validation directory or validation log
is created.

WSL regressions passed: compilation, existing logger and workflow self-tests,
and an actual two-step 420-424 s restart. Continuity passed before production;
progress reported 422/424 s at dt 2 s; summary contained only 420/422/424 s;
physical-time checkpoint/dump/PVD output was produced; lineage and validation
semantics were correct. SHA-256 hashes of the parent manifest, summary, and
420 s checkpoint were identical before and after. Temporary regression artifacts
were removed. The full 420-1800 s production continuation was not run.
